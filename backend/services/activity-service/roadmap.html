3. Правила и инварианты

Критические бизнес-правила

  • Дата начала активности должна быть не раньше чем через 1 час от текущего времени.
  • Если активность LIMITED, то число занятых активных слотов никогда не должно превышать maxParticipants.
  • Если minParticipants задан, он не может превышать maxParticipants.
  • FREE → PAID и изменение цены после появления подтверждённых / оплаченных участников запрещено.
  • Критические изменения после публикации требуют уведомления участников, а часть изменений — полного запрета.
  • Только автор может дублировать проведённую активность в новую.
  • Удаление активности заменяется на cancel / archive, чтобы не терять историю.
  • Создание, join, cancel, waitlist promotion и смена capacity идут только в транзакциях под блокировкой.

Антиспам и ограничения

Лимит на создание новых активностей за 1 час / 24 часа.
Лимит на число одновременно опубликованных будущих активностей.
Content similarity check для почти одинаковых title / description / links / location.
Blocked URL masks: startsWith / contains / regex + разбор scheme/host/path.
Risk-based post-moderation и, в будущем, AI-модерация текста, ссылок и изображений.

4. География и eligibility

Offline / Online политика

ONLINE: country mismatch не блокирует участие.
OFFLINE: учитываем страну, город, расстояние и время до старта.
HYBRID: обе политики, в зависимости от выбранного режима участия.

Country mismatch policy

Если пользователь в другой стране и до старта мало времени — auto join блокируется.
Сценарий переводится в manual approval или показывается предупреждение.
Для доверенных пользователей политика может быть мягче.

Nearby-функции отдельно

Текущая геолокация устройства используется отдельно для nearby search.
Профильная локация не должна жёстко подменяться GPS без подтверждения пользователя.
Timezone — автоматически с устройства, country/city — optional suggestion с подтверждением.

5. Критические секции и блокировки

Где нужны блокировки

  • Join activity
  • Leave / cancel participation
  • Waitlist → approved promotion
  • Change maxParticipants
  • Start / cancel / complete activity
  • Payment reservation timeout release

Техническая стратегия

PostgreSQL transaction + SELECT ... FOR UPDATE на activity / capacity row.
Unique constraint на активное участие пользователя в активности.
Reservation statuses для платных активностей: PENDING_PAYMENT / CONFIRMED / EXPIRED.
Idempotency key или защита от double submit / retry.

6. Что должно быть в профиле пользователя

Я записался

Все активности, где пользователь был участником: pending, approved, attended, cancelled, no-show.

Я посетил

Только фактически посещённые активности. Полезно для trust, рекомендаций и достижений.

Я провёл

Активности, где пользователь был автором/организатором: проведённые, отменённые, дублированные.
